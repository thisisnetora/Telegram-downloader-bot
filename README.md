# 🤖 ربات دانلودر تلگرام

ربات تلگرام برای دانلود از **یوتیوب، اینستاگرام، تیک‌تاک و پینترست** — آماده استقرار روی Railway.

## ✨ امکانات

- 📺 یوتیوب: کارت اطلاعات ویدیو + انتخاب کیفیت (1080p / 720p / 480p / 360p) یا دانلود MP3
- 📸 اینستاگرام: ریلز، ویدیو و پست
- 🎵 تیک‌تاک: ویدیو و پست‌های عکسی
- 📌 پینترست: ویدیو و عکس (پین‌های تصویری هم پشتیبانی می‌شن)
- 📊 نمایش نوار پیشرفت دانلود
- 🧹 پاک‌سازی خودکار فایل‌های موقت
- ⚡ دانلود هم‌زمان چند کاربر (با محدودیت کنترل‌شده)

## 🚀 استقرار روی Railway

### ۱. ساخت ربات
1. در تلگرام به [@BotFather](https://t.me/BotFather) پیام بده
2. دستور `/newbot` رو بزن و اسم و یوزرنیم ربات رو بده
3. **توکن** دریافتی رو کپی کن

### ۲. آپلود کد روی GitHub
```bash
git init
git add .
git commit -m "Telegram downloader bot"
git remote add origin https://github.com/USERNAME/REPO.git
git push -u origin main
```

### ۳. دیپلوی
1. وارد [railway.app](https://railway.app) شو و با GitHub لاگین کن
2. **New Project → Deploy from GitHub repo** رو انتخاب کن
3. ریپوی ربات رو انتخاب کن — Railway خودش Dockerfile رو تشخیص می‌ده
4. از بخش **Variables** متغیر زیر رو اضافه کن:

| متغیر | مقدار |
|---|---|
| `BOT_TOKEN` | توکنی که از BotFather گرفتی |

5. چند ثانیه صبر کن — ربات آنلاینه ✅

> 💡 Railway نیاز به خرید سرور نداره؛ روی پلن Trial/Hobby اجرا می‌شه. ربات از long polling استفاده می‌کنه پس نیازی به دامنه یا پورت هم نیست.

## 🚚 جابه‌جایی به هاست دیگه (VPS / هر جا که Docker داره)

کل ربات کانتینریه — جابه‌جایی چند دقیقه طول می‌کشه:

```bash
git clone https://github.com/USERNAME/REPO.git
cd REPO
cp .env.example .env   # بعد متغیرها رو پر کن
docker compose up -d --build
```

- 📋 دیدن لاگ: `docker compose logs -f`
- 🔄 آپدیت: `git pull && docker compose up -d --build`
- 💾 آمار و کوکی‌ها روی volume دائمی (`/data`) می‌مونن — ری‌استارت یا ری‌بیلد چیزی رو پاک نمی‌کنه.

**انتقال آمار از Railway:** توی پنل `/admin` دکمه «💾 بکاپ آمار» رو بزن تا فایل `bot_data.json`
برات فرستاده بشه؛ بعد روی سرور جدید بذارش توی volume:

```bash
docker cp bot_data.json $(docker compose ps -q bot):/data/bot_data.json
docker compose restart
```

> 💡 اگه فعلاً روی Railway می‌مونی: از بخش **Volumes** یه Volume به مسیر `/data` اضافه کن و
> متغیرهای `DATA_FILE=/data/bot_data.json` و `COOKIES_FILE=/data/cookies.txt` رو ست کن تا
> دیگه با redeploy چیزی پاک نشه.

## 🔄 جابه‌جایی بین اکانت‌های Railway

**روش ۱ — انتقال مالکیت (سریع‌ترین، صفر داون‌تایم):**
توی پروژه: **Settings → Transfer Ownership** → اکانت دوم رو انتخاب کن.
کل پروژه با همه متغیرها، لاگ‌ها و Volume منتقل می‌شه و ربات اصلاً خاموش نمی‌شه.

**روش ۲ — Deploy تازه روی اکانت دوم (~۲ دقیقه):**
1. **اکانت ۱:** بخش **Variables** رو باز کن — یه لیست از همه متغیرها بردار (یا با
   «Raw Editor» همه رو یکجا کپی کن). توی پنل `/admin` دکمه «💾 بکاپ آمار» رو بزن.
2. **اکانت ۲:** **New Project → Deploy from GitHub repo** → همین ریپو رو انتخاب کن.
3. از بخش **Variables → Raw Editor** همه متغیرهای کپی‌شده رو paste کن.
4. اگه آمار می‌خوای: Volume اضافه کن (مسیر `/data`)، فایل بکاپ رو بذار توش، Redeploy.

> 💡 به‌محض اینکه اکانت ۲ بالا اومد و ربات جواب داد، سرویس اکانت ۱ رو خاموش کن
> (تا دوتا ربات هم‌زمان روی یه توکن کار نکنن — تلگرام فقط به یکی update می‌ده).

## 🍪 کوکی (حل خطاهای یوتیوب و اینستاگرام)

یوتیوب روی IP سرورهای ابری دو سد داره که ربات هر دو رو خودکار رد می‌کنه:

1. **بلاک bot** (`Sign in to confirm you're not a bot`) → با **کوکی** مرورگر رد می‌شه
2. **قفل PO Token روی فرمت‌ها** (`Requested format is not available`) → با پلاگین
   **`bgutil-ytdlp-pot-provider`** که **داخل ایمیج Docker ساخته شده** و موقع دانلود
   خودکار توکن تولید می‌کنه، رد می‌شه. نیازی به هیچ تنظیمی نیست — فقط Redeploy کن.

ربات موقع استارت توی لاگ نشون می‌ده که هر کدوم فعالن یا نه:
`PO-token provider: ✅, cookies: ✅`

> ⚠️ **اگه `Sign in to confirm you're not a bot` گرفتی:** یعنی کوکی باطل/منقضی شده.
> یوتیوب کوکی رو با هر بار لود صفحه rotate می‌کنه، پس اگه بعد از اکسپورت توی مرورگر
> روی یوتیوب کلیک کرده باشی، کوکی مُرده.

**نحوه اکسپورت درست کوکی (خیلی مهم):**

1. یه پنجره **Incognito/خصوصی** باز کن و توی اون وارد یوتیوب شو (لاگین کن)
2. افزونه «Get cookies.txt LOCALLY» رو باز کن و **بلافاصله** کوکی رو اکسپورت کن
   (بدون اینکه روی هیچ لینکی توی یوتیوب کلیک کنی — هر کلیک کوکی رو باطل می‌کنه!)
3. کل محتوای فایل رو بذار توی `COOKIES_CONTENT` (یا base64‌ش رو توی `COOKIES_B64`)
4. Redeploy کن. بعدش می‌تونی پنجره رو ببندی — فقط **از یوتیوب Sign out نکن**
   (Sign out کوکی رو فوری باطل می‌کنه). بستن پنجره Incognito حتی بهتره چون دیگه
   سهواً اون سشن رو استفاده نمی‌کنی و کوکی rotate نمی‌شه.

> ⏳ کوکی معمولاً چند روز تا چند هفته کار می‌کنه. هر وقت دوباره خطای `Sign in...`
> گرفتی، یعنی وقتشه همین مراحل رو با کوکی تازه تکرار کنی — نیازی نیست مرورگر باز بمونه.

**روی سیستم خودت:** فایل رو با اسم `cookies.txt` کنار `bot.py` بذار. (PO Token provider
فقط توی ایمیج Docker ساخته می‌شه؛ برای اجرای محلی بدون Docker لازم نیست.)

## 🔧 عیب‌یابی

- ربات حالا **دلیل دقیق خطا** رو توی پیام نشون می‌ده — اگر خطا گرفتی، متن دلیل رو چک کن
- yt-dlp مرتب آپدیت می‌شه چون یوتیوب سیستمش رو عوض می‌کنه؛ اگر ناگهان همه‌لینکا خراب شدن،
  توی Railway یه **Redeploy** بزن تا آخرین نسخه yt-dlp نصب بشه

## 🛠 اجرای محلی

```bash
pip install -r requirements.txt
# ffmpeg هم باید نصب باشه
set BOT_TOKEN=توکن-ربات
python bot.py
```

## 🛠 پنل مدیریت (اختیاری)

با ست کردن `ADMIN_IDS` (آیدی عددی ادمین‌ها، با کاما جدا کن) دستور `/admin` فعال می‌شه:

- 📊 آمار کامل: کاربران، دانلودهای کل و امروز، دانلودهای ناموفق
- ✅ تعداد عضویت‌های تأییدشده در کانال (کل و امروز)
- 📺 تفکیک دانلود بر اساس پلتفرم + آپتایم و نسخه yt-dlp
- 📢 **ارسال پیام همگانی** به همه کاربران (متن، عکس، ویدیو...) با گزارش موفق/ناموفق

> آیدی عددیت رو از [@userinfobot](https://t.me/userinfobot) بگیر. آمار در فایل `DATA_FILE`
> (پیش‌فرض `bot_data.json`) ذخیره می‌شه و روی Railway تا redeploy بعدی باقی می‌مونه —
> برای ماندگاری دائمی، یه Volume به Railway اضافه کن و `DATA_FILE=/data/bot_data.json` ست کن.

## 🔒 جوین اجباری (عضویت اجباری در کانال)

کاربر تا عضو کانال تو نشه، نمی‌تونه از ربات استفاده کنه:

1. ربات رو در کانالت **ادمین** کن (حتماً!)
2. متغیر `FORCE_JOIN_CHANNEL` رو با یوزرنیم کانال ست کن، مثلاً `@mychannel` (بدون `@` هم قبوله)
3. اگر کانال **خصوصی**ه، متغیر `FORCE_JOIN_LINK` رو با لینک دعوت کانال هم ست کن

> ✅ ربات موقع استارت خودش چک می‌کنه که به کانال دسترسی داره و ادمینه — اگه مشکلی باشه
> توی لاگ Railway با خطای `FORCE JOIN` مشخصه. اگه جوین اجباری کار نمی‌کنه، اول لاگ رو چک کن.

## ⚙️ متغیرهای محیطی

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `BOT_TOKEN` | — | **اجباری** — توکن ربات از BotFather |
| `FORCE_JOIN_CHANNEL` | — | یوزرنیم کانال برای جوین اجباری، مثلاً `@mychannel` |
| `FORCE_JOIN_LINK` | — | (اختیاری) لینک دعوت — برای کانال خصوصی |
| `COOKIES_CONTENT` | — | محتوای فایل کوکی (Netscape format) — روش پیشنهادی روی Railway |
| `COOKIES_B64` | — | کوکی به‌صورت base64 (ضدخرابکاری — جایگزین COOKIES_CONTENT) |
| `COOKIES_FILE` | `cookies.txt` | مسیر فایل کوکی (برای اجرای لوکال) |
| `BOT_API_URL` | — | آدرس سرور Bot API محلی برای آپلود تا ~۲ گیگابایت |
| `MAX_FILE_MB` | `49` | سقف حجم فایل به مگابایت |
| `ADMIN_IDS` | — | آیدی عددی ادمین‌ها با کاما — فعال‌سازی `/admin` |
| `DATA_FILE` | `bot_data.json` | مسیر فایل ذخیره آمار پنل مدیریت |

## 📦 آپلود فایل‌های بیشتر از ۵۰ مگابایت (تا ~۲ گیگابایت)

API رسمی تلگرام سقف ۵۰ مگ داره. برای بیشتر، یک سرویس دوم روی Railway با
ایمیج رسمی `telegram-bot-api` بالا میاری:

1. از [my.telegram.org](https://my.telegram.org) → **API development tools** یک اپ بساز و `API_ID` و `API_HASH` رو بگیر
2. توی Railway روی پروژه‌ت: **+ Create → Docker Image** → ایمیج: `aiogram/telegram-bot-api:latest`
3. **Custom Start Command** این سرویس:
   ```
   telegram-bot-api --api-id=API_ID --api-hash=API_HASH --local --http-port=8081
   ```
   (مقادیر واقعی رو جایگزین کن)
4. توی تنظیمات همین سرویس، **Private Networking** رو فعال کن
5. توی سرویس ربات این متغیرها رو بساز:
   - `BOT_API_URL` = `http://<نام-سرویس>.railway.internal:8081`
   - `MAX_FILE_MB` = `1000`
6. Redeploy

> ⚠️ نکته: فایل‌های خیلی بزرگ روی پلن رایگان Railway ممکنه به محدودیت RAM/دیسک بخورن.
